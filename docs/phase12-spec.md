# Phase 12 実装仕様 — 技術

企画書 `docs/design.md` §5 の「技術国家を目指す」と §15 の Action 例「研究」を
実装する。

## 0. 方針

### 現状

技術は**実装されていないし、企画書もほぼ書いていない。** 言及は 2 か所だけ。

- §5 の国家戦略の例に「技術国家を目指す」→ `NationalFocus::Technocracy`
  として実装済み（生産速度と建設速度の係数。研究ではない）
- §15 の RL の Action 例に「研究」の 1 語 → 対応する `Action` はない

**何を研究するのか、どう効くのかは一行も書かれていない。**
意図して外したのではなく、検討されたことがない。

### 何を技術とするか

所有者との相談（2026-09-12）で 3 軸に決めた。**いずれも既存の値に係数を
掛ける形で、新しいシミュレーション領域を作らない。**

| 軸 | 効く先 |
|---|---|
| 民間の生産性 | `economy` の生産（食料・エネルギー・機械） |
| 軍需の生産性 | 軍需品と装備の生産 |
| 兵科ごとの装備 | `Branch` の戦闘係数 |

### 代償は時間だけ

**在庫を消費しない。** 研究のために備蓄を割く形にはしない。

判断は「研究するかどうか」ではなく「**どの軸を先に、どれだけ**」である。
3 軸への配分なので、軸の間に機会費用がある。

### ただし速度は経済に依存する

**研究の進行は機械の生産と労働力に比例する。** 工業地帯を取られたり、
補給を断たれたり、徴兵で労働力を削れば、自然に遅くなる。

これにより**新しい攻撃目標を作らずに**、既存の戦争が研究に効く。
研究所をノードとして置く案は採らない（ノード種別をまた増やすことになる）。

## 1. 形

`Faction` が 3 軸それぞれに進捗と配分を持つ。配分は既存の
`industry_priority` / `logistics_priority` と同じ形にする。

- 配分は比率で按分する。**固定の優先順位を置かない**（規約 §6）
- 進捗は**一方通行のアキュムレータにしない。** 上限を持たせるか、
  失う経路を持たせるか、いずれかを選んで理由を述べる
- 効果は**逓減**させる。研究が進むほど次の 1 単位が効かなくなる形にしないと、
  時間が経つほど一方的に強くなる

### 効果の上限

**先に研究した側が勝つゲームにしてはいけない。** 企画書 §2 の主題は
国家システムの維持であって、技術競争ではない。

係数の上限を決め、**その値を「意味」で正当化すること。** 特定のシナリオが
望ましく振る舞うように合わせない（CLAUDE.md にその失敗が 3 件記録されている）。

---

## 2. 行動

`Action` に研究配分の設定を足す。`SetIndustryPriority` と同じ形。

**`Action::layer()` はワイルドカードなしの網羅マッチ**なので、
どのレイヤーに属させるかを必ず決めることになる。経済か大戦略かを
実装時に決めて理由を述べる。

---

## 3. AI と観測

### AI

`HeuristicAgent` が配分を選ばないと、AI 同士の対戦で新しいレイヤーが
実質的に無効になる（Phase 9D・10D・11C で 3 回踏んだ形）。

最低限、**状況に応じて軸を選ぶ**こと。選ばない版との差を数値で示す。

### 観測

3 軸の進捗と配分を出す。観測長は伸びる。`python/env` の行動表は `/schema` から
組み立てるので、**新しい行動が自動的に到達可能になることを確認する**
（Phase 11 で 6 つの行動が黙って到達不能になっていた）。

### 画面

研究の状態が見えること。既存の政策パネルに足す。
**撮って目で確認する。**

## 5. 受け入れ基準

### Stage 12A

- `cargo build --workspace` 警告 0、`cargo test --workspace` 全通過
- `cargo tree -p archipelago-sim` が空のまま
- **3 シナリオの結果が 12A 前とバイト一致する**
- 進捗が一方通行でない（選んだ形の回復・上限がテストで固定されている）

### Stage 12B

- **3 軸それぞれが、対応する値を実際に動かす**
- 効果が逓減する。上限に達する
- 研究の速度が機械の生産と労働力に依存する。**工業地帯を失えば遅くなる**

### Stage 12C

- 観測長が `GET /schema` から取れ、`python/` のテストが通る
- **新しい行動が RL の行動表から到達可能**（`/schema` 由来の検査が通る）
- AI が軸を選ぶ。選ばない版との差を数値で示す
- 画面で研究が見える

### Stage 12D

- japan_hex で 720 日を完走し、受け入れテストの閾値を維持する
- **「先に研究した側が勝つ」になっていないことを測る。** 研究を止めた勢力と
  進めた勢力を同じ seed で比べ、差が決定的でないことを示す
- `--bench` で Phase 11 との比較値を出す

**バランスは japan_hex で測る。mvp はデバッグ用であり、ここでは読まない。**

## 共通の制約

`docs/conventions.md` に従う。特に:

- `crates/sim` は外部クレート依存 0、Bevy 非依存、完全決定論
- フォールバック禁止。ビジネスロジックは型で
- 希少な資源に固定の優先順位を置かない。比率で按分する
- 一方通行のアキュムレータを作らない
- テストは落ちうることを確認してから信用する
- 各ステージの完了時に `codex review --uncommitted` を通す
