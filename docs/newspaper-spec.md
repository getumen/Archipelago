# 新聞の仕様 — 国に何が起きたかを語る

企画書 `docs/design.md` の「イベント生成」「新聞・報道」を実装し直す。
現在の実装は出来事の種類を並べているだけで、企画書の意図を満たしていない。

## 0. なぜ作り直すか

3 回目の手動プレイテスト（2026-09-12）で次が観測された。

- 270〜300 日の号に「輸送路線 X が攻撃を受け輸送力が低下した」がほぼ同文で
  15 回並ぶ
- **同じ期間に市民と労働者の支持が崩壊していたことに一言も触れない**

企画書の例文は構造を示している。

> 「名古屋工業地帯への攻撃によって生産能力が低下。政府は被害を限定的と
> 発表している。」

**原因 → 国への影響 → 政府の言い分。** 現在の実装はこの 3 つのどれも
満たしていない。§23 が掲げる「一つの歴史が生まれた」の水準にない。

## 1. 何が 1 号を駆動するか

**その期間に国の状態がどう動いたかが軸で、出来事はその根拠として引く。**
出来事の列挙ではない。

見るべき状態（すべて既存の値。新しいものを足さない）:

| 領域 | 値 |
|---|---|
| 政治 | 7 グループの支持、安定度、戦争支持、ストライキ・抗議・regime change |
| 経済 | 品目ごとの在庫と不足、配給率、輸入量 |
| 軍事 | 部隊数（兵科別）、戦死、補給率 |
| 領土 | 地域数、占領、戦災 |
| 輸送 | 路線の状態、ノードの稼働 |

**期間の始点と終点の差を取り、大きく動いたものから語る。** 何も動いて
いなければ「静穏な期間」と書いてよい（現在もそうしている）。ただし
**支持が崩壊しているのに静穏と書くことは許されない。**

### 出来事は根拠

同種の出来事はまとめる。「15 回の空襲を受けた」であって、15 行ではない。
**出来事の行数が号の長さを決めてはいけない。**

## 2. 政府の言い分

企画書の例文の「政府は被害を限定的と発表している」に相当する層を入れる。

論調は**安定度と支持から決まる。** 苦しいときほど楽観的な発表になる、という
形にすれば、**新聞そのものが国の状態を語る情報源**になる。プレイヤーが
「発表が空々しい」と感じたら、それが情報である。

論調と実態の乖離を、プレイヤーが**画面の他の場所と突き合わせて**確かめられる
こと。新聞だけが唯一の情報源にならないようにする（政治パネルには既に
グループごとの支持と余裕が出ている）。

## 3. テンプレートを主とする

現状は LLM がないと読めるものにならない。**逆にする。**

- テンプレートだけで「読める新聞」が成立すること
- LLM は**さらに自然な文章にする層**として上に乗る
- `--agent llm --backend fail` と `--agent heuristic` の一致は維持する

規約 §3 の「許可済みの例外」に新聞のテンプレートは既に載っている
（LLM の失敗時に機械的要約へ落ちる）。**その落ち先が読めるものである**ことを
この仕様で保証する。

## 4. 不変条件

- **新聞はシミュレーションを変えない。** `--newspaper` の有無で `--json` が
  バイト一致することを維持する
- 決定論。同じ seed・同じ日なら同じ号
- `crates/agents` は Bevy 非依存

## 5. 受け入れ基準

- **支持が崩壊した期間の号が、それに言及する。** 現在は言及しない。
  これがこの仕様の存在理由であり、テストで固定する
- **同種の出来事が 15 行に展開されない。** まとめられている
- **論調が状態で変わる。** 安定しているときと崩れているときで文面が異なる
- LLM なしで読める。`--backend fail` で生成した号を人が読んで判断する
- `--newspaper` の有無で結果が変わらない
- 3 シナリオで 720 日を完走し、受け入れテストの閾値を維持する

**「読める」は人が読んで判断する。** 行数や文字数では測らない
（CLAUDE.md「画面は見る。数えない」）。

## 既知の限界 — 期間内で往復した変化は語られない

号は期間の**始点と終点の 2 点**を比べる。したがって、支持が期間の途中で
崩壊して終点までに回復した場合、差し引きがゼロになり語られない。

`codex review` が「静穏な期間」と誤って書く経路を 3 つ見つけ、うち 2 つ
（領土の等量交換、全部失敗した空襲）は mover の大きさの取り方を直して塞いだ。
3 つ目のこれは**直していない。**

理由。塞ぐには期間内の最小値・最大値を追う必要があり、2 点の差分という
この設計の骨格を変えることになる。支持は日単位ではゆっくり動くので、30 日の
期間内に崩壊と完全な回復が収まることは実際には起きにくい。**起きにくいと
判断して見送った**のであって、見落としではない。

もし実際に観測されたら、そのときは期間内の標本を取る設計に変える。
**先に測ること。**

## 共通の制約

`docs/conventions.md` に従う。特に:

- フォールバック禁止（規約 §3 の許可済み例外を除く）
- 新しい状態を足さない。既存の値から語る
- テストは落ちうることを確認してから信用する
