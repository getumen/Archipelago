# コーディング規約

このリポジトリで守る規約。**すべての実装作業はこの文書に従うこと。**
各 Phase の仕様書（`docs/*-spec.md`）はこの規約を前提とする。

## 1. 設計

- **エクストリームプログラミング禁止。**
  ビジネスロジックに対する抽象を勝手に導入しない。抽象化が必要だと判断したら、
  実装せずに提案し、相談してから決める。
- **ビジネスロジックはなるべく型で実装する。**
  実行時の検証よりも、不正な状態を表現できなくすることを優先する。
  例: 政策値は素の `f32` ではなく 0〜1 を保証する型で持ち、
  不正な値をそもそも構築できなくする。
- **継承禁止。移譲を使う。**
  Rust では、基底クラス代わりのトレイト既定メソッドによる実装共有や、
  `Deref` を使った継承もどきを禁じる。合成して明示的に委譲する。

### 既存コードへの適用

**まとめてのリファクタリングはしない。** この規約は、

- 新しく書くコード
- **既に書かれたコードのうち、その作業で触る部分**

に適用する。ボーイスカウト方式で、触ったところを規約に沿った形へ直していく。
規約に反する箇所を見つけても、その回の作業と無関係なら手を出さない
（見つけたことは報告してよい）。

大規模な一括改修による回帰リスクを避けるための方針であり、
規約を緩めるものではない。触る以上は直す。

## 2. テスト

- **TDD 禁止。** 古典主義の BDD で書く。実物のオブジェクトと実際の振る舞いを検査する。
- **モックは外部と通信する箇所にのみ使う。** 現状の該当は LLM バックエンドのみ
  （`MockBackend` / `ScriptedBackend`）。内部の型に対するモックやテストダブルを作らない。
- テストは**落ちうることを確認してから**信用する。
  このリポジトリでは、機構が壊れていても緑のままになる回帰ガードが 2 件、
  実物が壊れていても通る画素統計による検証が 1 件見つかっている。
  「通ること」は「守れていること」を意味しない。

## 3. エラーと失敗

- **フォールバック原則禁止。**
  「X が使えなければ黙って Y にする」経路を作らない。欠けているなら欠けていると示す。
  実装が必要だと判断したら、**必ず許可を求める**。
- **fail-fast。**
  設計書に明記されていないエラーハンドリングを書かない。
  防御的な握り潰し、暗黙の回復、ベストエフォートの劣化を追加しない。

### 許可済みの例外

以下は明示的に許可されたフォールバックである。**これ以外を追加しないこと。**

| 箇所 | 挙動 | 理由 |
|---|---|---|
| `crates/agents` `LlmAgent` | バックエンドの失敗・壊れた応答では直前の `Doctrine` を維持し、有効な `Doctrine` を一度も得ていなければヒューリスティックの既定動作に落ちる | LLM は本質的に落ちる外部依存であり、障害でゲームが遊べなくなることを避ける。`--agent llm --backend fail` の実行結果が `--agent heuristic` とバイト一致することで担保している |
| `crates/agents` 新聞生成 | LLM の失敗時は機械的なテンプレート要約を出す | 同上。新聞はゲーム状態に影響しない純粋な出力であり、欠けても整合性は壊れない |

### 適用範囲の注記

`Simulation::apply` が不正な行動を捨てて `ActionError` を返す挙動は
フォールバックではない。`docs/mvp-spec.md` §5 に明記された仕様であり、
RL エージェントが大量の不正行動を投げることを前提とした API 契約である。

## 4. 依存

- `crates/sim` は外部クレート依存 0、Bevy 非依存、完全決定論を維持する。
- `crates/agents` は Bevy に依存しない。
- Bevy は `apps/game` にのみ入る。
- `cargo build --workspace --exclude archipelago-game` が通ること。

## 5. 決定論

- `HashMap` / `HashSet` の反復順に依存する処理を書かない。
- 浮動小数の加算順序を固定する。
- 同じ seed と同じ入力列なら、必ず同じ結果になること。
- `scenarios/mvp.json` の seed 1 / 720 日のハッシュ
  `0138bf5d537417128e737d3fb68ff55591b8c5dc96e7f382cedaec3b63ffb714`
  は Phase 1 から不変であり、リファクタリングの回帰ガードとして機能している。

## 6. 繰り返し踏んだ欠陥

Phase 1〜6 で同型の欠陥を 12 件修正している。新しいコードでも警戒する。

- 希少な資源に**固定の優先順位**を置かない。必ず比率で按分する。
  意思決定で動かせないループは境界値で飽和する。
- **一方通行のアキュムレータ**を作らない。増える量には必ず戻る経路を持たせる。
- 1 tick の許容量は**減る予算**として持つ。残量に比率を掛け直す実装は、
  行動の連打で破られる（企画書 §15・§18 のとおり RL エージェントが操作する）。
- **発令時点の値を焼き込まない。** 現在の状態を追うべき値を一度だけ標本化しない。
- 状態には**必ず回復経路**を持たせる。入ったら出られない状態を作らない。
